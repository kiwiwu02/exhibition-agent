# 海外展会线索录入Agent - 设计文档

## 1. 项目概述

### 1.1 目标
高效、准确地记录、补充海外展会上获得的客户/代理商线索，助力海外销售工作。

### 1.2 核心功能
- **功能1**：名片录入 - 在飞书展会群里发送名片图片+文本，Agent自动识别并录入CRM
- **功能2**：AI自动信息调研 - 自动对公司做背调，生成调研报告

## 2. 架构设计

### 2.1 技术方案
**方案F：cc-connect + Claude Code + 飞书**

```
飞书群消息
    │
    ▼
┌─────────────────────────────────────┐
│  cc-connect (消息桥接)              │
│  • WebSocket连接飞书                │
│  • 接收/发送消息                     │
│  • 处理图片、文本                    │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Claude Code (AI Agent)             │
│  • 理解用户意图                      │
│  • 调用MiMo-V2.5识别名片            │
│  • 调用背调API获取公司信息           │
│  • 读写Bitable CRM                  │
│  • 生成飞书文档报告                  │
└─────────────────────────────────────┘
```

### 2.2 技术选型
| 组件 | 技术 | 说明 |
|------|------|------|
| 消息桥接 | cc-connect | 连接飞书和Claude Code |
| AI Agent | Claude Code | 理解意图、调用工具、生成回复 |
| 多模态AI | MiMo-V2.5 | 名片图片识别（通过API调用） |
| 背调搜索 | Tavily Search API | 结构化搜索，1000次/月免费 |
| 补充搜索 | Google Custom Search | 100次/天免费 |
| 公司信息 | Crunchbase API | 50次/月免费 |
| CRM存储 | 飞书多维表格(Bitable) | 结构化数据存储，自带界面 |
| 报告输出 | 飞书文档 | 结构化调研报告，自带界面 |

**无前端方案**：所有用户交互在飞书中完成
- 名片录入：飞书群消息 → cc-connect → Claude Code
- 重复确认：飞书群消息回复
- 查看CRM：飞书多维表格界面
- 查看报告：飞书文档界面

## 3. 功能1：名片录入

### 3.1 流程设计

```
飞书群消息
    │
    ▼
1. 消息解析 - 提取图片URL、文本补充、发送者信息
    │
    ▼
2. 图片下载 & 预处理 - 下载图片、质量检查、base64编码
    │
    ▼
3. 多模态AI识别 - 调用MiMo-V2.5，提取名片字段
    │
    ▼
4. 信息整合 - 合并AI结果+文本补充、字段标准化、数据验证
    │
    ▼
5. 重复检测 - 查询Bitable CRM，匹配邮箱/公司名/电话
    │
    ├─ 发现重复 → 发送确认消息给销售
    └─ 无重复 → 直接写入CRM
    │
    ▼
6. CRM写入 - 调用Bitable API创建记录，触发背调
```

### 3.2 MiMo-V2.5 配置与调用

#### API配置
```python
# config.py
MIMO_API_CONFIG = {
    "api_base": "https://api.mimo.ai/v1",  # 或本地部署地址
    "model": "mimo-v2.5",
    "api_key": "your-api-key",
    "max_tokens": 2000,
    "temperature": 0.1  # 低温度保证识别稳定性
}
```

#### 名片识别调用
```python
import base64
from openai import OpenAI

def recognize_business_card(image_path: str) -> dict:
    """使用MiMo-V2.5识别名片图片"""
    
    # 读取并编码图片
    with open(image_path, "rb") as f:
        image_data = base64.b64encode(f.read()).decode()
    
    client = OpenAI(
        api_key=MIMO_API_CONFIG["api_key"],
        base_url=MIMO_API_CONFIG["api_base"]
    )
    
    response = client.chat.completions.create(
        model=MIMO_API_CONFIG["model"],
        messages=[
            {
                "role": "user",
                "content": [
                    {
                        "type": "image_url",
                        "image_url": {
                            "url": f"data:image/jpeg;base64,{image_data}"
                        }
                    },
                    {
                        "type": "text",
                        "text": RECOGNITION_PROMPT
                    }
                ]
            }
        ],
        max_tokens=MIMO_API_CONFIG["max_tokens"],
        temperature=MIMO_API_CONFIG["temperature"]
    )
    
    return parse_recognition_result(response.choices[0].message.content)
```

#### 结果解析
```python
import json
import re

def parse_recognition_result(result: str) -> dict:
    """解析AI识别结果"""
    try:
        # 提取JSON部分
        json_match = re.search(r'\{[\s\S]*\}', result)
        if json_match:
            return json.loads(json_match.group())
    except json.JSONDecodeError:
        pass
    
    # 降级处理：返回空结果
    return {
        "company_name": "",
        "contact_name": "",
        "email": "",
        "phone": "",
        "confidence": {}
    }
```

### 3.3 重复检测方案

**混合方案**：规则匹配 + AI模糊匹配

```
新记录进入
    │
    ▼
规则匹配（快速、低成本）
    │
    ├─ 明确匹配 → 询问销售确认
    ├─ 明确不匹配 → 直接写入
    └─ 不确定 → AI模糊匹配
                    │
                    ├─ 高置信度 → 询问销售
                    └─ 低置信度 → 写入但标记可能重复
```

**匹配规则**：
- 规则1：邮箱完全匹配（高置信度）
- 规则2：公司名 + 联系人姓名匹配（中置信度）
- 规则3：公司名 + 电话匹配（中置信度）
- 规则4：AI模糊匹配（处理别名、缩写）

**飞书群内交互确认**：
```
⚠️ 检测到可能重复的线索

新录入：
- 公司：TechCorp Inc.
- 联系人：John Smith
- 邮箱：john@techcorp.com

已有记录：
- 公司：TechCorp Solutions
- 联系人：John Smith
- 邮箱：john.smith@techcorp.com

请确认：
1️⃣ 更新现有记录
2️⃣ 保留两条记录
3️⃣ 需要手动合并
```

## 4. 功能2：AI自动信息调研

### 4.1 流程设计

```
名片录入CRM成功
    │
    ▼
1. 触发背调任务 - 从Bitable读取公司信息
    │
    ▼
2. 多维度并行调用信息源
    │
    ├─ 【官网与社交媒体】官网分析、LinkedIn、Facebook/Twitter
    ├─ 【搜索引擎】Google搜索、谷歌地图/LBS地图
    ├─ 【商业数据库】海关数据、OpenCorporates、邓白氏
    └─ 【域名历史】Whois、Archive.org、SimilarWeb
    │
    ▼
3. AI分析整合信息（五大维度）
    │
    ├─ 基本面与赛道定位
    ├─ 规模与健康度
    ├─ 组织架构与决策链
    ├─ 动态与新闻
    └─ 合作案例与行业口碑
    │
    ▼
4. 交叉核实验证 - 多途径信息相互验证，标注可信度
    │
    ▼
5. 生成飞书文档报告 - 使用lark-cli创建，返回链接
    │
    ▼
6. 自动补充CRM字段 - AI背调自动填写以下字段：
    │
    ├─ 公司别名 - 公司其他名称/缩写
    ├─ 国家/地区 - 更精确的国家信息
    ├─ 区域 - 大区域（北美/欧洲/亚太等）
    ├─ 城市 - 更精确的城市信息
    ├─ 公司地址 - 详细办公地址
    ├─ 官网链接 - 官方网站URL
    ├─ 主营业务 - 核心业务描述
    ├─ 公司规模 - 员工人数范围
    ├─ 公司类型 - 上市/私营/初创等
    ├─ 行业分类 - 所属行业
    └─ 信用评级 - AI评估的信用等级
    │
    ▼
7. 写入报告链接到CRM
```

## 5. 用户交互流程

### 5.1 名片录入流程
```
销售在飞书展会群中：
1. 发送名片图片（手机拍照或电子版）
2. 可选：发送文本补充信息（如"这是采购总监，对传感器感兴趣"）

Agent处理：
1. 接收消息，识别图片和文本
2. AI识别名片信息
3. 检测是否重复
4. 无重复 → 直接写入Bitable，回复确认消息
5. 有重复 → 发送确认消息，等待销售回复

销售回复：
- 回复"1" → 更新现有记录
- 回复"2" → 保留两条记录
- 回复"3" → 标记需要手动合并
```

### 5.2 背调结果查看
```
销售在飞书中：
1. 打开多维表格 → 查看CRM数据和背调状态
2. 点击"调研报告"链接 → 打开飞书文档查看详细报告
3. 直接在表格中编辑补充信息
```

## 6. 测试用例

### 5.1 名片识别测试用例（4个场景）

#### 场景1：标准电子名片
- **输入**：标准商务名片，信息清晰

- **输入**：手机拍摄，15度倾斜，部分模糊

- **输入**：中英双语名片

- **关注**：中英文字段区分

```toml

level = "info"

[[projects]]
name = "exhibition-agent"

[projects.agent]
```

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| MiMo-V2.5识别不准确 | 名片信息错误 | 增加置信度标注，低置信度人工复核 |

| 跨境网络问题 | API调用超时 | 超时重试，降级方案 |
